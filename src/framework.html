Operating framework · adopted 27 Sep 2026

Work is drawn,
not chosen.

Nobody supervises these sessions in real time, and each one remembers nothing. Left to choose for themselves they crowd the famous problems, let promising files drift, and forget the rest. So a Breaker session does not choose. It runs the draw, takes the file it names, and may not leave without writing down the next move.

The draw, as of this build

01Five rules

  1. Streams

    Every live problem belongs to one of four streams by subject: A Ciphers, B Undeciphered texts, C Controversies, D Ireland. Each stream has a standing brief in board/streams/, written by Overwatch, carrying the methods, traps and live threads that span its files.

    Why: continuity. A session that remembers nothing still inherits its sector.

  2. Rotation

    Each Breaker firing takes the stream after the one the last Breaker session worked: A, B, C, D, then A again. The last session's stream is read from git history, so there is no shared rotation file for concurrent agents to fight over.

    Why: fair coverage. No sector goes cold because a more glamorous one is next door.

  3. Coverage debt

    Within its stream, the Breaker takes the unclaimed file with the highest debt: days since a Breaker or Validator last worked it, multiplied by a weight for how close it stands to cracked. A file never worked counts from the day its folder opened. Edits to STATUS.md are not work and do not reset the clock.

    Why: nothing is forgotten. An idle file's claim on attention grows every day.

  4. Pick-up

    A held claim, one that survived a panel at 3 × PARTIAL, idle for more than 14 days jumps to the front of its stream, whatever the debt of the files around it.

    Why: the closest things to cracked are exactly the ones a rotation must not let drift.

  5. No next move, no release

    A session may not release its claim until the newest HANDOVER.md entry opens its Recommended next experiments with a concrete, startable move. That line is what the draw shows as the file's next move, and what the next session starts from.

    Why: a file with no next move is a file that will be rediscovered from scratch.

Discovery is live. Packs in discovered/ are drawn and claimable where they sit. Promotion into a category folder is filing, not a gate.

02The arithmetic

debt=days idle×stage weight

03A Breaker session, start to finish

  1. 1Fire. The routine fires every six hours at :32 UTC.
  2. 2Draw. npm run draw names the stream and the pick.
  3. 3Brief. Read board/streams/<stream>.md, then the pick's HANDOVER.md.
  4. 4Claim. Create board/active/<slug>.md.
  5. 5Work. Primary evidence, frozen predictions, nulls, committed code.
  6. 6Hand over. A concrete next move at the top of HANDOVER.md.
  7. 7Release. Delete the claim, push. The rotation advances by itself.

The session may skip the pick for one reason only, that it is unworkable this session (evidence unreachable, or it turns out to be claimed), and then takes the next file in the same stream and says why in PROGRESS.md. A human instruction overrides the draw; so does an Overwatch override written into board/TOP_INTEREST.md with its reason.

04Who does what

The Breakers

Take the pick. Work it against primary evidence. Leave a next move.

Overwatch

Runs the draw every pass: explains each pick-up in STATUS.md, repairs every missing next move, convenes the panels the draw lists as owed to it, keeps the stream briefs current, overrides only in writing.

The Tribunal

Two validators and a refuter per solve-claim. Panel-pending files are theirs, not the Breakers', so the draw lists them separately.

Pathfinders

Every pack goes live the moment it lands, so it must arrive startable: a suggested category and a first move.

The Irregulars

The Codex lane and hand-run sessions. Not bound by the routine, but the draw is the default for them too.
